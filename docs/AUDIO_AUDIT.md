# 行为与音效对应检查

## 结论与证据边界

检查基线为 `2c47bfd`，覆盖六武器及进化、敌人预警/死亡、玩家受伤、拾取、结算、升级/暂停与 BGM。发现了具体的语义复用、持续时间、事件缺失与生命周期问题，已修正。

本次结论来自代码触发追踪、PCM 波形时长、实际 Web Audio 节点/输出采样、浏览器行为测试和视觉时间线。**没有进行人类盲听、手机扬声器或耳机听感验收，不能据此宣称“完美融合”。** 音色判断是明确的设计选择；同步、静音、优先级和声部回收有自动证据。

使用 [独立试听页](../audio-review.html) 对照单项与六武器混合。试听复用生产混音，预设时间用于比较行为，不是整局录音。

## 全行为检查表

| 行为 | 检查发现 | 当前处理与判断 |
| --- | --- | --- |
| 脉冲刃 / 光子幻刃 | 有目标时才挥切，每轮一个起音；0.18 秒样本对应 0.26 秒轨迹 | 保留空气挥切和轻金属边缘；±3% 音高微变减少重复。多目标仍一声，避免五次叠响 |
| 电弧 / 天罚 | 雷击在实际连锁/落雷释放时触发，0.85 秒原样本尾声长于闪光 | 保留雷击质感；自然衰减不要求与闪光同长。声音是整次释放，不对每条链重复播放 |
| 轨道卫星 / 环垒 | 只在接触或挡弹时发声，空转无声；短 0.12 秒撞击 | 保留轻撞与 230ms 共享限频，微小音高变化；挡弹沿用护盾材质音色，画面闪环区分动作 |
| 等离子 / 重炮发射 | 炮口闪光与每轮发射同步，多发弹体只发一声 | 保留 0.32 秒能量脉冲；短音高微变，不改变玩法随机序列 |
| 等离子命中 | 有冲击环和击退，原来非致命命中没有音效 | 补 0.11 秒能量碰撞，100ms 共享限频；击杀时用死亡声，避免碰撞与碎裂重复堆叠 |
| 黑洞生成 | 与玩家受伤共用 phaserDown1，容易混淆含义 | 独立 0.42 秒引力启动声；随生成位置衰减与左右定位 |
| 黑洞牵引 | 效果最长 3.4 秒，原来只有启动声 | 低音量周期持续层，跟随有效黑洞存活；多个黑洞合并为一个持续声，按最近黑洞定位 |
| 超新星爆发 | 玩家技能爆炸被归入重要提示，会压低其他攻击声 | 保留爆发声，归回普通战斗组，仍有较高抢占优先级；不把自己的输出当成危险提示 |
| 棱镜 / 裂隙 | 画面 0.45/0.65/1 秒，单发样本固定 0.48 秒；进化降调后约 0.565 秒 | 起音加低音量持续层，持续声由实际 beams.life 控制，结束约 30ms 淡出；三条光束共用一条持续声 |
| 狙击、扇射、冲锋蓄力 | 原来只有视觉预警 | 进入蓄力状态响一次短双脉冲；不逐帧响，不把提示声伪装为发射声；屏外预警静音 |
| Boss 地面危险圈 | 有圈但没有对应声音 | 危险圈生成时提示一次，持续使用视觉收缩/扩散表达倒计时；不在每个 tick 播放 |
| 普通怪 / 精英死亡 | 短碎裂能表达像素敌人解体；原来远处与近处同响 | 保留碎裂，普通/精英用不同音高音量；加轻微变化、距离衰减与左右定位，群死限频 |
| Boss 死亡 | 与普通怪共享碎裂素材，使用更低音高和更大音量 | 保留体量区分，并允许尾音与胜利声衔接；没有证明这一选择符合所有人的听感 |
| 玩家受伤 | 和黑洞同素材；高频攻击密集时可能误判自己掉血 | 独立 0.19 秒机体冲击；仅实际扣血后触发，无敌期碰撞不发声，保持重要提示优先 |
| 晶体拾取 | 旧样本 0.522 秒，常规变速后约 0.387 秒，但限频只有 65ms，容易叠成连续鸣叫 | 改为 75ms 晶体轻响，90ms 共享限频；大晶体稍高音，不随拾取数量堆叠音量 |
| 胜利 / 失败 | 正向/下行结算音色与结果含义一致 | 保留；只允许在结算状态播放，重开清除结果尾声 |
| 升级 / 进化选卡 | 用户明确要求静音、保留 BGM | 保持；清除所有战斗尾声与持续层，BGM 不重启 |
| 暂停 / 装备抽屉 / 静音 | 原来重要提示可能在暂停后继续响，静音后尚存节点可能恢复旧声 | 暂停与静音清理全部声部；继续时仅恢复仍有效的持续层，不重播发射、受伤等旧事件 |
| BGM | 独立 4% GainNode，升级连续，暂停/失焦停止 | 保留音乐与音量，不随普通攻击反复起伏；没有重新验证音乐审美或完整曲目接缝 |
| 通用命中 API | playHit 存在，但生产游戏没有调用，不能算作所有武器已有命中声 | 保留为短能量碰撞接口供测试/后续使用；不把它接到所有持续伤害 tick 上 |
| 脚步 / 敌人普通移动 / 祭司治疗 | 当前没有专用声音 | 保留安静，避免大群怪移动和每次治疗填满听觉；治疗范围与连线继续传递信息。这是取舍，不是“遗漏声音即 bug” |

## 参考的做法

1. **按动作状态分层，持续声随游戏状态结束。** [FMOD 官方人员的充能武器示例](https://qa.fmod.com/t/suggestions-for-implementing-charged-weapon-sound-in-game/13275) 将充能与发射拆开，并通过参数控制循环/阶段切换。本项目把同一原则用于引力场和持续射线，使用原生 Web Audio 实现。
2. **重要提示优先，限制同时发声。** [Wwise 的声部与优先级说明](https://www.audiokinetic.com/en/public-library/2024.1.8_8893/?id=optimizing_cpu&source=Help) 解释超出播放预算时如何舍弃声音。本项目保留武器合计 8、普通组 12、重要组 4、全局 20 的预算；持续层计入预算，低优先级持续声不能互相抢占造成每帧重启。
3. **减少重复，但保持动作身份。** [Wwise 随机容器](https://www.audiokinetic.com/en/public-library/2024.1.4_8780/?id=creating_random_container&source=Help) 介绍攻击/命中/反应声音的变化与限制重复。本项目采用成本较小的 ±3% 音高及 94%～100% 音量微变；它不等同于多份录音素材的随机容器。
4. **世界声音体现远近和方位。** [Wwise 声像与衰减](https://www.audiokinetic.com/en/library/edge/?id=working_with_2d_sound_music_and_motion_fx_objects&source=Help) 用位置和距离控制声像与响度。本项目最远 650 单位、左右声像不超过 ±0.65；玩家受伤和结算居中。不支持 StereoPanner 的浏览器退回单声道。

这些是可借鉴的设计方法，不是“行业规定的完美参数”。本项目没有安装 Wwise 或 FMOD，也没有增加运行依赖。

## 验证方式与听感复核

- `node tests/verify.cjs --growth --no-ogg`：全项目回归，包含实际攻击/命中/预警事件、持续层寿命与暂停恢复、混音输出、素材解码和独立试听页。
- `node tests/integrity.cjs`：验证器自身的正常对照与故障注入。
- `node tests/build-report.cjs`：生成源码匹配的验收报告；新专项证据在 `CURRENT_BENCHMARK.json` 的 `verification.audioActions`。
- 新增样本采用单声道 PCM WAV，离线合成，源脚本与 CC0 许可随仓库分发。

主观复核建议：手机外放先听“黑洞”和“受伤”是否能立即区分，再听“六武器混合”中的危险提示是否清楚；耳机检查左右声像是否自然。若音色仍不喜欢，应替换同一功能层的素材，不用抬高所有音量来掩盖问题。
